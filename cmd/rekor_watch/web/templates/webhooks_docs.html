Verifying signed webhooks

How to authenticate Rekor Watch webhook deliveries

Overview

Every webhook delivery is signed using the Standard Webhooks v1 scheme (HMAC-SHA256). Verify the signature on every request before trusting its contents. Each subscription has its own secret, so two subscriptions pointing at the same URL produce different signatures.

The payload envelope

The request body is JSON with a stable {type, timestamp, data} envelope:

{
  "type": "rekor.match.created",
  "timestamp": "2026-06-22T12:00:00Z",
  "data": {
    "monitored_value": { "type": "subject", "subject": "user@example.com" },
    "entries": [
      { "origin": "rekor.sigstore.dev - 123", "log_index": 42, "uuid": "abc..." }
    ]
  }
}

Switch on type to stay forward-compatible (rekor.match.created is the only type today).

Signature headers

Each delivery carries three headers:

  • webhook-id — a per-batch delivery ID (sub_<subID>-batch_<minMatchID>-<maxMatchID>). Use it as your primary idempotency key.
  • webhook-timestamp — Unix seconds when the delivery was signed. Regenerated and re-signed on every attempt.
  • webhook-signature — a space-separated list of v1,<base64> signatures (today just one).

Verification algorithm

  1. Take the secret revealed at create/regenerate time. It looks like whsec_<base64>. The HMAC key is the standard-base64 decoding of everything after whsec_.
  2. Build the signed string from the raw received bytes: {webhook-id}.{webhook-timestamp}.{rawBody}. Never parse-then-re-serialize the body — TLS-terminating proxies, WAFs, or ingress controllers that rewrite the body will break the signature.
  3. Compute HMAC-SHA256(key, signedString), base64 (standard) encode it, and compare it to the v1, value using a constant-time comparison.
  4. Reject deliveries whose webhook-timestamp is more than 300 seconds from now (keep your clock on NTP).
  5. Deduplicate on webhook-id, and secondarily on each entry's log_index/uuid. Acknowledge duplicates with a 2xx.

Example signed string:

sub_5-batch_10-20.1750593600.{"type":"rekor.match.created",...}

The Standard Webhooks reference libraries (including Go, Python, JavaScript, and more) implement this v1 HMAC verification out of the box. 

// Go, using crypto/hmac (no external dependency)
key, _ := base64.StdEncoding.DecodeString(strings.TrimPrefix(secret, "whsec_"))
mac := hmac.New(sha256.New, key)
mac.Write([]byte(id + "." + ts + "." + string(rawBody)))
want := "v1," + base64.StdEncoding.EncodeToString(mac.Sum(nil))
ok := hmac.Equal([]byte(want), []byte(receivedSignature))

Secrets: reveal-once and regenerate

The signing secret is shown only once — when you create the subscription or regenerate it. Store it securely; it cannot be shown again. If you lose it, regenerate to get a new one. Note that regenerating is a hard cutover: the old secret stops working immediately, so update your verifier with the new secret. If you subscribed before signing was enabled, regenerate once to obtain your secret.
